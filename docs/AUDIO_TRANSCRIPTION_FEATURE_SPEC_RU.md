# Техническое задание: транскрибация многочасовых аудиозаписей

## 1. Назначение

Добавить в Ouroboros возможность локально транскрибировать многочасовые аудиозаписи и формировать скачиваемые стенограммы.

Фича должна:

- поддерживать `.m4a`;
- использовать существующий `faster-whisper`;
- обрабатывать большие записи с ограниченным потреблением RAM;
- автоматически выбирать модель по продолжительности записи;
- сохранять таймкоды;
- показывать прогресс;
- продолжать обработку после прерывания;
- выдавать результат как task artifacts.

Обработка выполняется локально. Отправка аудио во внешние API в MVP не входит.

## 2. Текущее состояние

Существующий `ouroboros/local_stt.py`:

- использует `faster-whisper`;
- принимает один аудиофайл;
- по умолчанию использует модель `small`;
- возвращает одну строку текста;
- не сохраняет сегменты и таймкоды;
- не поддерживает чанкинг, прогресс и возобновление.

Telegram-интеграция запускает этот модуль для `.ogg` с таймаутом 180 секунд через `ouroboros/telegram_local_stt_patch.py`.

Загрузка через чат ограничена 50 МБ в `ouroboros/gateway/files.py`.

## 3. Функциональные требования

### 3.1. Входные форматы

Обязательная поддержка:

- M4A/MP4 Audio: AAC и ALAC;
- MP3;
- WAV;
- FLAC;
- OGG/Opus.

Расширение и MIME используются только для первичной фильтрации. После загрузки файл должен быть открыт через PyAV и проверен на наличие корректного аудиопотока.

Для M4A принимать:

- `.m4a` без учёта регистра;
- `audio/mp4`;
- `audio/x-m4a`;
- `application/mp4`.

### 3.2. Ограничения

Значения по умолчанию:

- максимальный размер: 1 ГБ;
- максимальная длительность: 12 часов;
- один файл на одну операцию;
- одна одновременно работающая транскрибация на worker;
- лимиты должны настраиваться через settings/env.

### 3.3. Пользовательский сценарий

1. Пользователь прикрепляет аудиофайл.
2. Просит агента подготовить стенограмму.
3. Агент автоматически вызывает `transcribe_audio`.
4. Пользователь получает сообщения:
   - проверка файла;
   - выбранная модель и основание выбора;
   - загрузка модели;
   - прогресс обработки;
   - формирование артефактов.
5. После завершения пользователь получает ссылки на Markdown, TXT и JSON.

Полный текст стенограммы нельзя возвращать в tool result или помещать в LLM-контекст.

## 4. Архитектура

Добавить общий модуль:

```text
ouroboros/transcription.py
```

Он отвечает за:

- проверку аудио;
- получение метаданных;
- duration-based routing;
- потоковое декодирование;
- чанкинг;
- вызов Whisper;
- объединение результатов;
- checkpoint;
- формирование стенограмм.

Поток обработки:

```text
Аудиофайл
  → валидация контейнера
  → определение длительности
  → выбор модели
  → потоковое декодирование PyAV
  → mono 16 kHz
  → чанки с перекрытием
  → faster-whisper
  → глобальные таймкоды
  → дедупликация стыков
  → checkpoint
  → MD/TXT/JSON artifacts
```

Системный `ffmpeg` не должен быть обязательной зависимостью. Основной декодер — PyAV, поставляемый кроссплатформенно.

## 5. Версии и модели

Использовать:

```text
faster-whisper==1.2.1
```

Версию необходимо синхронно зафиксировать в:

- `requirements.txt`;
- `pyproject.toml`;
- lock-файле.

Поддерживаемые модели:

- `large-v3` — максимальное качество;
- `turbo` — баланс качества и скорости;
- `medium` — CPU для коротких записей;
- `small` — CPU/economy fallback.

Модели сохраняются в существующем каталоге:

```text
data/models/faster-whisper
```

## 6. Duration-based model routing

### 6.1. Основная политика

При `model="auto"`:

| Устройство | Продолжительность | Модель |
|---|---:|---|
| CUDA/GPU | до 30 минут включительно | `large-v3` |
| CUDA/GPU | более 30 минут | `turbo` |
| CPU | до 15 минут включительно | `medium` |
| CPU | более 15 минут | `small` |

Для неизвестного устройства применяется GPU/general policy. Если фактическая инициализация CUDA не удалась, выполняется CPU routing.

### 6.2. Конфигурация

```text
TRANSCRIPTION_MODEL_ROUTING=duration
TRANSCRIPTION_MODEL_ROUTES=1800:large-v3,*:turbo
TRANSCRIPTION_CPU_MODEL_ROUTES=900:medium,*:small
TRANSCRIPTION_ALLOW_MODEL_FALLBACK=true
```

Формат правила:

```text
<максимальная длительность в секундах>:<модель>,*:модель
```

Правила проверяются при загрузке settings. Некорректная конфигурация не должна приводить к запуску случайной модели — использовать встроенные значения и записать warning.

### 6.3. Ручное переопределение

Инструмент принимает:

```text
model="auto" | "large-v3" | "turbo" | "medium" | "small"
```

Явно указанная модель отключает duration routing.

Если пользователь просит «максимальное качество», агент передаёт:

```text
model="large-v3"
```

### 6.4. Fallback

При OOM или невозможности инициализировать модель:

```text
large-v3 → turbo → small
turbo    → small
medium   → small
```

Fallback применяется только к ошибкам загрузки модели или нехватки RAM/VRAM. Произвольные ошибки декодирования и распознавания не должны вызывать смену модели.

Пользователь обязательно получает предупреждение. В метаданных сохраняются requested model и actual model.

Модель выбирается один раз на весь файл и не меняется между чанками.

## 7. Чанкинг

Параметры по умолчанию:

```text
TRANSCRIPTION_CHUNK_SEC=900
TRANSCRIPTION_OVERLAP_SEC=2
```

Ограничения:

- размер чанка: 60–3600 секунд;
- перекрытие: 0–10 секунд;
- перекрытие всегда меньше чанка.

Алгоритм:

1. PyAV потоково декодирует аудио.
2. Поток преобразуется в mono PCM 16 kHz.
3. В памяти находится не более одного чанка и overlap-буфера.
4. Чанк передаётся одной загруженной модели Whisper.
5. Локальные таймкоды переводятся в глобальные.
6. После чанка результат атомарно записывается в checkpoint.
7. Временный PCM освобождается.

Рекомендуемые параметры Whisper:

```python
vad_filter=True
word_timestamps=True
condition_on_previous_text=False
beam_size=5
```

При автоматическом определении языка язык фиксируется после первого речевого чанка с достаточной уверенностью и используется для оставшейся записи.

## 8. Объединение чанков

Для чанков используется шаг:

```text
step = chunk_duration - overlap
```

Сегменты в области перекрытия распределяются по midpoint:

- первый чанк принимает сегменты до середины правого overlap;
- промежуточный чанк принимает сегменты между серединами левого и правого overlap;
- последний чанк принимает всё после середины левого overlap.

Дополнительно удаляется повтор, если:

- временные интервалы пересекаются;
- нормализованные тексты совпадают либо имеют высокую схожесть;
- разница начала/окончания находится в допустимом пороге.

Итоговые сегменты должны иметь монотонные таймкоды и не пересекаться нелогичным образом.

## 9. Checkpoint и возобновление

Идентификатор операции рассчитывается из:

- SHA-256 исходного файла;
- размера файла;
- модели или версии routing;
- языка;
- параметров чанкинга;
- значимых параметров Whisper.

Checkpoint хранится в:

```text
data/state/transcriptions/<job_id>/checkpoint.json
```

Структура:

```json
{
  "schema_version": 1,
  "job_id": "...",
  "status": "running",
  "source": {
    "path": "...",
    "sha256": "...",
    "size": 123456,
    "duration_sec": 10842.5
  },
  "requested_model": "auto",
  "selected_model": "turbo",
  "fallback_from": null,
  "language": "ru",
  "completed_chunks": 4,
  "total_chunks": 13,
  "segments": []
}
```

Checkpoint сохраняется атомарно после каждого чанка.

При повторном запуске:

- совпавшие параметры — продолжить с первого незавершённого чанка;
- изменившийся файл или параметры — создать новую операцию;
- уже распознанные чанки повторно не отправлять в Whisper.

Аудиочанки между запусками хранить не требуется.

## 10. Инструмент агента

Добавить:

```text
ouroboros/tools/transcription.py
```

Tool contract:

```text
transcribe_audio(
    path: string,
    model: string = "auto",
    language: string = "auto",
    chunk_duration_sec: integer = 900,
    overlap_sec: integer = 2,
    output_formats: array = ["md", "txt", "json"]
)
```

Tool result:

```json
{
  "ok": true,
  "job_id": "...",
  "duration_sec": 10842.5,
  "language": "ru",
  "requested_model": "auto",
  "selected_model": "turbo",
  "routing": {
    "strategy": "duration",
    "matched_rule": "*:turbo"
  },
  "resumed": false,
  "segments_count": 1432,
  "artifacts": [
    {"name": "recording.transcript.md"},
    {"name": "recording.transcript.txt"},
    {"name": "recording.transcript.json"}
  ]
}
```

Требования:

- добавить `transcribe_audio` в `CORE_TOOL_NAMES`;
- добавить модуль `transcription` в `_FROZEN_TOOL_MODULES`;
- таймаут инструмента — 12 часов;
- зарегистрировать как foreground long-running tool;
- разрешать только пути из attachment uploads, `user_files`, `task_drive`, `artifact_store` или активного workspace;
- запретить произвольные системные пути.

## 11. Прогресс и отмена

События прогресса:

```text
Проверяю аудиофайл…
Продолжительность: 03:00:42. Выбрана модель turbo.
Загружаю модель…
Обрабатываю чанк 4 из 13 — 31%.
Формирую стенограмму…
```

Требования:

- обновлять прогресс после каждого чанка;
- во время долгого чанка обновлять его не чаще одного раза в минуту;
- использовать текущий progress event mechanism;
- отмена задачи должна прекращать обработку;
- после отмены worker не должен оставлять фоновые процессы;
- завершённые checkpoint-данные сохраняются для повторного запуска.

## 12. Загрузка больших аудиофайлов

Добавить endpoint:

```text
POST /api/audio/upload
```

Не увеличивать общий 50-МБ лимит для остальных chat attachments.

Требования endpoint:

- multipart upload;
- потоковая запись блоками;
- лимит `OUROBOROS_AUDIO_UPLOAD_MAX_BYTES`, по умолчанию 1 ГБ;
- предварительная проверка `Content-Length`;
- контроль фактически записанных байтов;
- проверка свободного диска;
- временное имя `.uploading`;
- атомарное переименование;
- удаление частичного файла при ошибке;
- валидация контейнера после загрузки;
- удаление файла при провале валидации.

Frontend должен автоматически использовать этот endpoint для поддерживаемых аудиоформатов.

CLI `--attach` продолжает передавать локальный путь без загрузки через HTTP.

## 13. Выходные артефакты

### Markdown

```markdown
# Стенограмма: recording.m4a

- Продолжительность: 03:00:42
- Язык: ru
- Модель: turbo

[00:00:03 — 00:00:11] Добрый день. Начинаем совещание.

[00:00:12 — 00:00:20] Первым вопросом будет...
```

### TXT

Тот же текст с таймкодами, без Markdown-заголовков.

### JSON

```json
{
  "schema_version": 1,
  "source": {
    "filename": "recording.m4a",
    "duration_sec": 10842.5,
    "sha256": "..."
  },
  "transcription": {
    "language": "ru",
    "requested_model": "auto",
    "selected_model": "turbo",
    "routing_rule": "*:turbo"
  },
  "segments": [
    {
      "start": 3.12,
      "end": 11.48,
      "text": "Добрый день. Начинаем совещание."
    }
  ]
}
```

Артефакты сохраняются через существующий task artifact store и доступны через текущий API скачивания task artifacts.

## 14. Обработка ошибок

Пользовательские ошибки должны быть понятными:

- файл не найден;
- неподдерживаемый формат;
- повреждённый контейнер;
- отсутствует аудиопоток;
- неподдерживаемый кодек;
- превышен размер;
- превышена длительность;
- недостаточно диска;
- не удалось загрузить модель;
- недостаточно RAM/VRAM;
- исходный файл изменился;
- задача отменена;
- checkpoint повреждён.

Повреждённый checkpoint перемещается в backup, после чего операция начинается заново с предупреждением.

В runtime-логи нельзя записывать полный текст стенограммы. Допустимы:

- job ID;
- имя файла без полного системного пути;
- длительность;
- модель;
- номер чанка;
- процент выполнения;
- санитизированная ошибка.

## 15. Совместимость с Telegram

Telegram voice transcription должна переиспользовать общий модуль, но сохранить текущее поведение:

- входной формат `.ogg`;
- модель по умолчанию `small`;
- язык из `TELEGRAM_STT_LANGUAGE`;
- текстовый результат без обязательного создания стенограммы;
- существующие `TELEGRAM_STT_*` остаются рабочими.

Для коротких Telegram voice messages duration routing по умолчанию не включать.

- ручное переопределение модели;

### Integration-тесты

- реальный небольшой M4A/AAC fixture;

### End-to-end

Тестовая запись продолжительностью не менее трёх часов:

- успешно принимается через web UI;

- обрабатывается чанками;
- не вызывает линейного роста RAM;
- показывает прогресс;
- возобновляется после принудительного прерывания;
- выдаёт три корректных артефакта.

## 18. Критерии приёмки

Фича считается готовой, если:

1. Агент принимает M4A размером более 50 МБ.
2. AAC и ALAC внутри M4A корректно декодируются.
3. Модель автоматически выбирается по длительности и устройству.
4. Явно указанная модель имеет приоритет над routing.
5. Одна модель используется для всех чанков файла.
6. RAM не растёт пропорционально полной длительности записи.
7. Пользователь получает регулярный прогресс.
8. После прерывания обработка продолжается с checkpoint.
9. На стыках чанков нет явных дублей.
10. Таймкоды монотонны и относятся к полной записи.
11. Создаются MD, TXT и JSON artifacts.
12. Полная стенограмма не попадает в tool result и runtime-логи.
13. Отмена не оставляет фоновых вычислений.
14. Telegram `.ogg` продолжает работать без изменения UX.
15. Тесты проходят в Docker и packaged desktop runtime.

## 19. Не входит в MVP

- diarization и подписи спикеров;
- облачный `gpt-4o-transcribe`;
- перевод аудио;
- редактирование стенограммы в UI;
- одновременная обработка нескольких файлов;
- суммаризация содержания записи.

Эти возможности должны проектироваться как отдельные расширения поверх JSON-сегментов готовой стенограммы.
